# PDS 应用接入指南（适用于全部系统）

> PDS 是客户总体架构中横跨各层的统一权限，所有系统都按同一套方式接入，**PDS 不为任何一个系统写专门逻辑**。
> 本指南适用于：应用层（票付通 3.0、景数通、数字大脑、畅游、各类 APP）、查数层（PDQ、PBI、PAP/PDA）、数据出口（PDT、PDK、PDD）、离线治理 PDG、实时治理 PDE、数据清洗（PDP、PDL、PDR）、数据集成 PDC、公共底座 PBS、回流平台。

---

## 1. 接入三步

| 步骤 | 做什么 | 接口 |
|---|---|---|
| ① 注册应用与权限清单 | 声明本系统的权限点（菜单/按钮/接口/AI 能力）和可授权的资源类型；PDS 自动生成**应用准入权限** `{app}:access` | `POST /api/v1/apps/{app}/manifest` |
| ② 创建 OAuth 客户端 | 页面类系统用"授权码 + PKCE"做单点登录；后台服务用"客户端凭证"调用 PDS；需要代表用户调用其他系统的用"令牌交换" | `POST /api/v1/apps/{app}/clients` |
| ③ 集成鉴权 | 登录态校验（JWT + JWKS）→ 拉取权限快照（缓存）→ 功能权限、数据范围、资源实例过滤 → 上报审计 | `/api/v1/authz/*`、`/api/v1/audit/events` |

## 2. 应用编码与分类

应用编码为小写字母开头的字母数字（2–32 位），也是权限点前缀。权限点格式：`{app}:{资源}:{动作}`。

| 分类 `category` | 含义 | 建议应用编码 |
|---|---|---|
| `APPLICATION` | 应用层 | `pft`（票付通）、`jst`（景数通）、`brain`（数字大脑）、`cy`（畅游）、各 APP 自定 |
| `QUERY` | 查数层 | `pdq`、`pbi`、`pap`、`pda` |
| `SECURITY` | 统一权限 | `pds`（内置） |
| `DATA_OUTLET` | 数据出口 | `pdt`、`pdk`、`pdd` |
| `OFFLINE_GOVERNANCE` | 离线治理 | `pdg` |
| `REALTIME_GOVERNANCE` | 实时治理 | `pde` |
| `DATA_CLEANSING` | 数据清洗 | `pdp`、`pdl`、`pdr` |
| `DATA_INTEGRATION` | 数据集成 | `pdc` |
| `FOUNDATION` | 公共底座 | `pbs` |
| `FEEDBACK` | 回流平台 | `fbk` |

## 3. 权限清单示例

```json
POST /api/v1/apps/pdd/manifest
{
  "name": "PDD 数据服务",
  "category": "DATA_OUTLET",
  "version": "2026.11.1",
  "accessControl": true,
  "permissions": [
    {"code": "pdd:dataset:view",   "name": "查看数据集",   "type": "FUNCTION"},
    {"code": "pdd:dataset:export", "name": "导出数据集",   "type": "FUNCTION", "risk": "HIGH"},
    {"code": "pdd:api:call",       "name": "调用数据 API", "type": "API"},
    {"code": "pdd:api:publish",    "name": "发布数据 API", "type": "FUNCTION", "risk": "HIGH"}
  ],
  "resourceTypes": [
    {"type": "pdd:dataset", "name": "数据集"},
    {"type": "pdd:api",     "name": "数据 API"}
  ]
}
```

- 清单可反复提交：新增/更新权限点；**清单中不再出现的权限点自动停用**（保留历史授权，不再生效）。
- **权限树（V2）**：`type` 为权限树节点类型编码（如 `MENU`、`BUTTON`、`API`、`DATA`、`FIELD`、`AI_TOOL`），类型在 PDS 后台维护，清单引用了不存在的类型会自动新增；可选字段 `parent` 指定父节点编码，用于组成"应用 → 域 → 菜单 → 按钮"的层级。授予父节点即包含其全部非高风险下级，禁止父节点即禁止全部下级。
- **修改编码**：已发布节点的编码可在权限树中"修改编码"（可连同下级前缀一起改），授权与角色权限自动迁移。默认保留原编码兼容：鉴权检查按原编码等同新编码、快照同时返回新旧编码、清单再次提交原编码不会新建节点；应用改用新编码后，管理员在"兼容编码"中移除原编码。修改时向该应用推送 `perm_node.recoded` 事件（`data.changes[]` 为 `oldCode → newCode`）。
- 管理员在 PDS 后台改过的节点（名称、风险、位置等）不会被清单覆盖；后台新增的节点不会因清单中没有而被停用。后台新增的节点须**发布**后才生效，发布后编码锁定；可在权限树中"导出为权限清单"交给应用开发对接。
- `{app}:access` 由 PDS 自动生成（名称"登录进入{应用名}"）；`accessControl` 默认 `true`，即人员须被授予该权限才能单点登录进入该系统。
- 调用方：PDS 管理员（`pds:app:manage`），或该应用自己的客户端（scope `pds.manifest`）。PDA 新增工具、技能、模型时由其客户端自动提交清单，新权限点默认无人拥有。

### 各系统的典型资源类型（参考）

| 系统 | 资源类型（可按实例授权） | 典型权限点 |
|---|---|---|
| PDK 知识服务 | `pdk:kb` 知识库 | `pdk:search:use`、`pdk:doc:download` |
| PDA / PAP 智能体平台 | `pap:agent` 智能体、`pda:skill` 技能 | `pda:tool:{工具}`、`pda:model:{模型}` |
| PDQ 即席自助 | `pdq:datasource` 数据源、`pdq:table` 表 | `pdq:query:run`、`pdq:sql:export` |
| PBI 数易 BI | `pbi:dashboard` 看板、`pbi:screen` 大屏、`pbi:cockpit` 驾驶舱 | `pbi:dashboard:edit`、`pbi:share` |
| PDT 标签中心 | `pdt:tag` 标签、`pdt:metric` 指标 | `pdt:tag:define`、`pdt:metric:publish` |
| PDD 数据服务 | `pdd:dataset`、`pdd:api` | `pdd:api:call`、`pdd:dataset:export` |
| PDG 离线治理 | `pdg:project` 项目、`pdg:table` 表、`pdg:job` 任务 | `pdg:job:run`、`pdg:quality:rule` |
| PDE 实时治理 | `pde:stream` 数据流、`pde:alert` 预警 | `pde:job:deploy`、`pde:alert:manage` |
| PDP / PDL / PDR | `pdp:pipeline`、`pdl:task` 标注任务、`pdr:task` 质检任务 | `pdl:label:review`、`pdr:sample:check` |
| PDC 数据集成 | `pdc:source` 数据源、`pdc:sync` 同步任务 | `pdc:source:manage`、`pdc:sync:run` |
| 应用层系统 | 按业务自定，如 `pft:channel` 渠道 | 按菜单/按钮声明 |

资源动作统一为 `READ`（查看/使用）⊂ `WRITE`（编辑）⊂ `ADMIN`（管理/授权）。

## 4. 资源实例注册与授权

```json
POST /api/v1/resources
{"type": "pdd:dataset", "refId": "ds_ticket_daily", "name": "门票日汇总", "scenicId": "org_xxx", "ownerId": "u_xxx"}
```

- `scenicId` 为资源所属景区；`GROUP` 表示集团共享资源。景区资源只对景区范围内的人员生效（景区隔离）。
- 授权：`POST /api/v1/resources/{type}/{refId}/grants`，可授权给人员/岗位/组织（可含下级）/用户组，效果 `ALLOW` 或 `DENY`，可设有效期。
- 资源的 `ADMIN` 持有者可以在本系统内对该资源发起授权（例如 PDK 知识库管理员在 PDK 后台授权），授权数据保存在 PDS。

## 5. 客户端类型

| 场景 | 授权方式 | 范围（scope） |
|---|---|---|
| 系统前端/门户单点登录 | `authorization_code` + PKCE（+ `refresh_token`） | `openid profile` |
| 后台服务查权限 | `client_credentials` | `pds.authz`（仅本应用）/ `pds.authz.all`（跨应用，如网关） |
| 注册权限清单、资源实例 | `client_credentials` | `pds.manifest`、`pds.resource` |
| 上报审计 | `client_credentials` | `pds.audit` |
| 代表用户调用其他系统（如 PAP/PDA 调 PDK、PDQ 调 PDD） | `urn:ietf:params:oauth:grant-type:token-exchange` | `{目标应用}.api` |

**令牌交换规则（通用）**：请求参数 `audience={目标应用编码}`、`scope={目标应用}.api`；目标应用必须已在 PDS 注册，发起方客户端必须登记了 `{目标应用}.api` 范围。签发的票据：`aud` = 目标应用，`act.sub` = 发起方客户端，有效期以客户端配置为准（建议 5 分钟）。审计中可区分"本人操作"与"代办"。

> 回调地址使用 HTTPS 域名；本地开发使用 `http://127.0.0.1:端口`（不能使用 `localhost`，OAuth 2.1 安全要求）。

## 6. 鉴权集成

1. **校验令牌**：用 `{issuer}/oauth2/jwks` 验签，校验 `iss`、`exp`、`aud`。人员令牌主要声明：`sub`/`uid`（人员 ID）、`name`、`emp_no`、`dept_id`、`scenic_id`、`scenic_scope`、`authz_ver`。
2. **权限快照**：`GET /api/v1/authz/snapshot?app={app}&subject={uid}`，返回权限点、数据范围、景区范围、可访问资源实例、最高密级；本地缓存（建议 5 分钟），令牌中 `authz_ver` 变大时立即刷新。
3. **单点判断**：`POST /api/v1/authz/check`、`POST /api/v1/authz/batch-check`（≤100 项），返回 `allowed` 与中文 `reason`。
4. **数据范围**：`ALL` 不限；否则满足其一即可：本人创建（`self`）、组织 ∈ `orgIds`、组织在 `orgTreeIds` 子树内、景区 ∈ `scenicIds`、领域 ∈ `domainIds`。角色上未声明数据范围时按"本人景区范围"处理。
5. **PDS 不可用时**：使用未过期的缓存快照只读降级；缓存也失效则拒绝，**不得默认放行**。
5.1 **角色（V2）**：快照返回 `roles`（此人与本应用相关的角色编码，配置了外部编码映射时为外部编码）与 `visible`（因下级被授予而"路径可见"的上级节点，如菜单，用于渲染导航，不等于拥有）；单点登录签发的访问令牌带 `roles` 声明（可在"系统角色 → 下发状态"中按应用关闭）。
6. **审计上报**：`POST /api/v1/audit/events`（每批 ≤500 条），事件的 `app` 以客户端所属应用为准。格式见下一节。

### 6.1 审计事件格式

```json
POST /api/v1/audit/events
{
  "events": [{
    "eventType": "AI_CHAT",
    "userId": "u_xxx", "userName": "张三", "via": "pda-gateway",
    "scenicId": "org_xihu", "ip": "10.1.2.3", "traceId": "7f3c…",
    "targetType": "pdk:kb", "targetIds": "kb_ticket",
    "action": "团体票退改规则是什么？",
    "result": "ALLOW",
    "detail": {
      "question": "团体票退改规则是什么？",
      "empNo": "S001023",
      "tools": [{"name": "pdk_search", "result": "ALLOW"}],
      "hitDocs": ["票务管理制度 v3.pdf", "团体票操作手册.docx"],
      "masked": 2, "maskedSample": "手机号 138****5678",
      "latencyMs": 2300,
      "mfa": false
    }
  }]
}
```

| 字段 | 说明 |
|---|---|
| `eventType` | `AI_CHAT`（问答）、`AI_TOOL_CALL`（工具调用）、`DATA_ACCESS`（检索/查数）、`DATA_DOWNLOAD`、`DATA_EXPORT`、`MASK_REVEAL`（查看脱敏原文）、`ACCESS_DENIED`（越权拦截）等；工作台"AI 使用概况"按前三类与后三类统计 |
| `result` | `ALLOW` / `DENY` / `FAIL` |
| `scenicId` | 发生时的景区；为空表示集团。审计中心按景区筛选、工作台按景区统计都依赖该字段 |
| `detail` | 自由 JSON，审计中心按以下约定字段展示，其余字段原样保存：`question` 问题原文（缺省用 `action`）；`empNo` 工号；`tools[]`（`name`、`result`）或单个 `tool`；`hitDocs[]` 命中文档名或仅 `hitDocCount`；`masked` 脱敏处数、`maskedSample` 脱敏示例（**只放脱敏后的文本**）；`latencyMs` 耗时；`mfa` 是否经二次认证；`reason` 拒绝原因 |

每条事件入库时计算哈希并链接上一条，管理后台可对单条记录（`GET /api/v1/audit/events/{id}/verify`）或全链（`GET /api/v1/audit/verify`）校验是否被篡改。

## 6.2 下发事件（V2，Webhook）

应用在 PDS"系统角色 → 下发状态 → 下发方式"中开启 Webhook 推送并填写地址后，PDS 在以下变化时推送事件：

| 事件 | 说明 |
|---|---|
| `perm_tree.published` | 本应用的权限树发布了新版本（含变更明细） |
| `perm_node.recoded` | 权限编码被修改（含新旧编码对照、是否保留原编码兼容） |
| `role.updated` | 角色权限、父角色、启停或外部编码变化 |
| `role.members.changed` | 角色绑定增减（`added` / `removed` 为受影响人员） |
| `role.deleted` | 角色删除 |
| `role.full_sync` | 全量对账：角色定义与完整成员清单，应用侧以此为准校正 |

请求体：`{"id","type","app","occurredAt","authzVersion","data":{...}}`，`data.externalCode` 为该角色在本应用的外部编码。请求头：`X-PDS-Event`、`X-PDS-Delivery`、`X-PDS-Timestamp`、`X-PDS-Nonce`、`X-PDS-Signature`。

**验签**：`hex(HMAC-SHA256(secret, timestamp + "." + nonce + "." + 原始请求体)) == X-PDS-Signature`，且时间戳与当前时间相差不超过 5 分钟、随机串未使用过。返回 2xx 视为成功；失败按 10 秒、30 秒、2 分钟、10 分钟重试，第 5 次仍失败标记为失败，可在后台重推。收到任一事件后也应以权限快照为准刷新缓存。
